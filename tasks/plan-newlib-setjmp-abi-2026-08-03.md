# Plan: fix newlib `setjmp`/`longjmp` under `-compiler=llvmz80`

Status: INVESTIGATED, root cause VERIFIED, fix designed (mirrors an already-proven
classic-clib fix). Not yet implemented — awaiting go-ahead.
Test: `test/clang/runtime_setjmp.sh` (the sole remaining newlib_iy FAIL).

## Symptom (observed, verified)

`runtime_setjmp` PASSES on classic, FAILS on the newlib routes
(`-clib=newlib_iy`/`newlib_ix`). Program:

```c
if (setjmp(jb) == 0) { puts("A_SETJMP0"); stage=1; longjmp(jb,1); }
else                 { printf("B_AFTER_LONGJMP stage=%d\n", stage); }
puts("C_DONE");
```

Newlib output: `B_AFTER_LONGJMP stage=0` then `C_DONE` — i.e. the **direct**
`setjmp()` call returned NONZERO (jumped straight to the else branch, `A_SETJMP0`
never printed, `stage` never set). Test verdict: "setjmp() did not return 0 on
direct call."

Reproduce (MUST set BOTH vars — the test reads `${ZCC_CLIB:-}`; setting only
TEST_CLIB silently builds classic and masks the bug):

```sh
TEST_CLIB=newlib_iy ZCC_CLIB="-clib=newlib_iy" sh test/clang/runtime_setjmp.sh
```

## Root cause (VERIFIED from source, not guessed)

`l_setjmp.asm` always returns 0 in **HL** on the direct call
(`ld hl,0 / and a / ret`) and reads its `env` pointer off the **stack**; that is
the classic stack-arg + HL-return convention == `__smallc` == `sdcccall(0)`.

The newlib header `include/_DEVELOPMENT/common/setjmp.h` (generated by m4 from
`proto/setjmp.h`) declares:

```c
extern int  __LIB__ l_setjmp (jmp_buf *env)          __SMALLC;   // __OPROTO
extern void __LIB__ l_longjmp(jmp_buf *env,int val)  __stdc;     // __SPROTO
```

In `include/sys/compiler.h`, the block `#if __SDCC | __clang__ | __XCC`
(lines ~31-40) defines **`__SMALLC` and `__stdc` as EMPTY** for clang. The later
`#if __clang__` block wires `__smallc = __attribute__((sdcccall(0)))` and (for
llvmz80) `__vasmallc = __smallc`, but **never maps the uppercase `__SMALLC`**
(nor `__stdc`) to `__smallc`. So under llvmz80 `l_setjmp` carries NO convention
attribute -> clang falls back to its default `sdcccall(1)`, which reads a 16-bit
return from **DE**. `l_setjmp` put 0 in HL, DE holds garbage -> `setjmp()` reads
nonzero on the direct call and every round-trip breaks.

Exact same ABI class as regex #39 (regcomp) and the variadic-stdio #31 fix.

## Why classic already passes (the reference fix)

`include/setjmp.h` (classic, hand-maintained) was ALREADY fixed for this exact
bug — it declares BOTH functions with lowercase `__smallc`, with a comment
describing precisely this symptom:

```c
extern int __LIB__ l_setjmp (jmp_buf *env)          __smallc;
extern int __LIB__ l_longjmp(jmp_buf *env, int val) __smallc;
```

`__smallc` is a no-op / native keyword for sccz80 and SDCC (they already use this
convention), so it is safe for all three compilers. The newlib `_DEVELOPMENT`
header simply never received the same treatment.

## Fix (mirror the classic fix into the newlib header)

Edit the m4 SOURCE `include/_DEVELOPMENT/proto/setjmp.h` so both symbols get the
`__smallc` convention, then regenerate `common/setjmp.h`:

```c
// must not use callee or fastcall linkage
#if defined(__LLVMZ80)
// llvmz80/clang: __SMALLC / __stdc expand empty (sys/compiler.h clang branch),
// so the default sdcccall(1) reads the return from DE and setjmp() "returns
// non-zero on the direct call". l_setjmp/l_longjmp are stack-arg + HL-return
// (sdcccall(0)); pin __smallc, mirroring the classic include/setjmp.h fix.
extern int __LIB__ l_setjmp (jmp_buf *env)          __smallc;
extern int __LIB__ l_longjmp(jmp_buf *env, int val) __smallc;
#else
__OPROTO(,,int,,l_setjmp,jmp_buf *env)
__SPROTO(,,void,,l_longjmp,jmp_buf *env,int val)
#endif
```

Regenerate (Makefile rule `common/%.h: proto/%.h  ->  m4 $^ > $@`):

```sh
cd include/_DEVELOPMENT && m4 proto/setjmp.h > common/setjmp.h
```

Commit BOTH the proto edit and the regenerated common/setjmp.h (they must stay
in sync; the tree ships the generated common/ headers, and cpm.cfg puts
`-isystem .../_DEVELOPMENT/common` on the newlib line).

### Arg-order note (why no reversed-arg forwarder is needed here)

Unlike regex #39 (whose sccz80 `__smallc` worker read the FIRST arg from the
DEEPEST slot, forcing an arg reversal), the setjmp workers are cdecl-order:
`l_longjmp` pops `env` (shallow) then `val` (deep) == first-arg-shallowest, which
is exactly what clang `sdcccall(0)` produces. So `__smallc` matches directly, no
forwarder. This is corroborated by the classic fix, which declares the identical
2-arg `l_longjmp` as `__smallc` and PASSES.

## Risk / blast radius

LOW and contained:
- Change is `#if defined(__LLVMZ80)`-guarded and touches ONLY the two setjmp
  symbols — NOT the global `__SMALLC` macro. (A blanket `__SMALLC -> sdcccall(0)`
  in compiler.h was REJECTED: 90 headers use uppercase `__SMALLC`, many multi-arg
  with `_callee` variants whose arg order would flip — a large, risky audit.)
- The fix is a proven pattern: the classic header already ships it and passes.
- Header-only; no library rebuild, no binary artifact regen.
